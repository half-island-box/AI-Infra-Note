> 为什么要量化？
> **减少模型显存占用**：单参数占哟个降低 -> 模型空间减小
> **提高推理计算速度**：低精度浮点运算速度更快
> **提高KV Cache缓存命中率**：相同大小的缓存空间可以存放更多低精度参数



## 量化的对象
|对象|数据的特点|主要收益|
|---|---|---|
|**权重（Weight）**|训练完成后固定，可提前处理|缩小模型、减少权重读取量|
|**激活（Activation）**|随当前输入变化|为低精度矩阵乘法提供输入，减少部分中间数据开销|
|**KV Cache**|随请求和上下文增长|降低每个历史 Token 的缓存成本|

- **W4A16** 中的 W 是 Weight，A 是 Activation，后面的数字分别表示位宽：
	权重用 4-bit，激活用 16-bit。
	**W8A8** 则表示两者都用 8-bit。
	这里的 A 包括送入线性层的输入及网络中的中间激活；它与权重一起参与计算，也可以被量化。

- W/A 记号只说明权重和激活的位宽，
	**不能据此认为模型中的所有数据都采用同一种精度。**
	KV Cache 的位宽也需要单独说明。


## 数值映射、Scale和Zero-Point
### 量化和反量化：大模型量化的本质
**大模型量化，不等于 直接降低目标参数的精度**
大模型量化本质 就是“压缩存储 + 近似还原”。

#### 量化：参数的压缩存储
量化，是**把一个高精度数值，映射为一个低位宽整数编码q**：
		`q=round(x/s​+z)`

- x：原始高精度值
- s：缩放因子（scale）
- z：零点（zero-point）
- q：量化后的低位宽整数

> 零点：让量化区间平移
> eg: 原分布[z,-z], 目标分布[0,2z], 这时候就需要加上零点来对应


**关键点**：q 本身不是真实的数值，它只是一个“编码/索引”。
就像字典里的页码，页码本身不代表词义，但能帮你定位到词义。


#### 反量化：编码q + 量化参数 -> 近似数值
反量化是根据编码 qq 和量化参数（s,z）还原出一个**近似**的原始值：
		x^=s⋅(q−z)`

- x^：还原出的近似值
- 注意是 x^而不是 x，因为量化是有损的，**不可能完全还原**
	可以**认为量化把连续的实数空间压缩到了有限个离散点上**
	还原出来的数值，只是某个对应点，不一定代表原数值

### 不同量化精度的误差差异
因为b个比特，最多有2^b  种位模式，所以：

| 位宽    | 编码数 | 相邻重建值间隔                    | 区间内最近舍入的最大绝对误差 |
| ----- | --- | -------------------------- | -------------- |
| 8-bit | 256 | 1/255≈0.003921/255≈0.00392 | 约 0.00196      |
| 4-bit | 16  | 1/15≈0.066671/15≈0.06667   | 约 0.03333      |
| 2-bit | 4   | 1/3≈0.333331/3≈0.33333     | 约 0.16667      |
可知，编码越少，覆盖范围与舍入误差之间的取舍越明显

## 量化粒度
**量化需要选定具体的行或列的粒度**，
比如：

|粒度|Scale 的共享范围|直观影响|
|---|---|---|
|**Per-tensor**|整个张量一组|元数据少，但一个大值就可能增大整个张量的量化步长|
|**Per-channel**|每个通道一组|隔离通道间的幅值差异；权重常按输出通道设置|
|**Per-group**|通道内再分组，例如每 128 个权重一组|局部范围更贴合，Scale 和零点数量增加|
**粒度越细，通常越容易拟合局部范围，**
**代价是需要保存更多 Scale、零点，并增加相应的读取与计算。**

选择粒度时，需要同时考虑误差和这些额外成本。


## 校准：确定激活值的量化误差范围

**校准（Calibration）就是：
用一小批有代表性的数据跑一遍模型，统计各张量（尤其是激活）的实际数值范围，据此确定 Scale 和零点（或对称量化的 Scale）**

> 权重参数是静态的，
> 但是激活值是动态：它随着输入的变化而变化
> 所以需要模型跑小批量数据来确定范围

校准输出的核心是**每个需要量化的张量的统计量**，最常见是：
- 全局 min/max；
- 分位数（如 99.9% 分位），用于裁掉极端离群值；
- 直方图，用于最小化 KL 散度等更精细的搜索。
    

对**权重**：静态统计，校准只是读取，不需要跑数据（但 Per-channel/Per-group 要按轴统计）。

对**激活**：必须跑校准数据，按选定粒度统计：
- Per-tensor：整个张量一个范围；
- Per-token：每行一个范围；
- Per-channel：每列一个范围。
    

**校准决定的是“范围”，范围决定 Scale/零点，Scale/零点决定量化误差。**


### PTQ和QAT：两种基本的量化思路

| 维度     | PTQ            | QAT                |
| ------ | -------------- | ------------------ |
| 需要什么   | 已有模型，视方法需要校准数据 | 可训练模型、训练数据与算力      |
| 怎样控制误差 | 校准、变换、局部重建     | 通过训练适应量化约束         |
| 适合何时尝试 | 快速部署、先建立低比特基线  | PTQ 未达到质量目标，且有训练条件 |
| 仍需验证什么 | 下游质量与实际部署收益    | 导出后的真实量化模型与部署收益    |
### PTQ：训练后量化
**PTQ（Post-Training Quantization，训练后量化）**
从已训练好的模型出发，选择量化参数（确定粒度->校准->计算scale和零点）
并视方法调整权重以减小误差，
最后导出量化模型。

它**不需要重新跑完整训练，适合作为部署的起点。**

### QAT：量化感知训练
**QAT（Quantization-Aware Training，量化感知训练）**
在训练或微调时模拟量化误差，让参数逐步适应这些误差。

前向常插入“量化→反量化”的 Fake Quantization，
反向用直通估计器（STE）等方法近似处理不可导的取整。

训练期间**通常仍保留高精度参数，最终再转换为真实低比特存储与计算**。

一般步骤：
1. 在原高精度模型中**插入伪量化节点**
	PyTorch 的 `torchao` API 中，这一步对应 `step="prepare"`，
	它会把普通的 `nn.Linear` 替换成带伪量化的版本。

2. 微调：让权重“补偿”量化误差
	**前向传播经过了伪量化，损失函数里包含了量化误差**。
	优化器的目标变成了：
	调整 FP32 权重，使得模型在“被量化噪声污染”的情况下也能表现良好。

3. 转换：换成真正的量化算子
	训练完成后，**固化量化节点记录的合适的scale和零点**
	永久量化权重

4. 部署与验证
