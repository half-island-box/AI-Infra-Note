
> W4A16，**让激活保留FP16/BF16， 只把权重压到4-bit**
> 问题在于，**4-bit的压缩表示，只有16个编码**，相比8-bit格距大了很多
> **关键在于让误差少伤输出**



## GPTQ：边量化边补偿

如果按照直觉，只按计算前的权重参数量化恢复，
目标即为最小化||W-W^||^2
（默认每个权重独立舍入，误差各自累积）

**但是经过线性层之后，有的误差会被输入放大，有的则会相互抵消**

**GPTQ的核心思路则是：**
	**在每次量化完一个权重后，把它造成的误差窟窿，**
	**用还没量化的权重给补回去**
	保证的是量化后的层输出，和量化前尽量一样，而不是看量化后的权重本身

### 工作机制
#### Hessian的概念和意义

Hessian矩阵，通常用`H = X ^ X_t`，即矩阵和自身转置的乘积
可以认为是某个Linear相对于权重参数的二阶导数矩阵：
![[Pasted image 20261112175242.png]]

那么其意义可以表述为：
	**某一层权重发生微小扰动时，该层输出误差变化的曲率**
	即衡量层中哪些权重对输出最敏感

量化的目标，即最小化层的输出误差：min || WX - W^ X || ^2
	![[Pasted image 20261112175809.png]]

#### Hessian矩阵在GPTQ的意义
这个 Hessian 矩阵在量化中扮演“敏感度地图”的角色：

1. **对角线元素**：
	H_ii表示第 i 个输入通道的激活值平方和，**反映该通道的“能量”。**
	对角线值大的通道，其对应权重的小扰动会被放大成较大的输出误差。
    
2. **非对角线元素**：
	Hij​ 刻画了第 i 和第 j 个输入通道之间的相关性。
	如果两个通道高度相关，
	**单独量化其中一个造成的误差，可以通过调整另一个来部分补偿**
	——这正是 GPTQ 逐列量化时利用的信息。

#### 逐列量化 + 误差补偿
GPTQ 把权重矩阵 **按列（column）** 一列一列地处理，从左到右。
这个过程借用了经典的 **OBS（Optimal Brain Surgeon）** 更新规则。

1. **量化当前列**：
	假设正在处理第 q 列。先把它量化（比如四舍五入到最近的整数），
	得到量化后的值，同时也就知道了这一列产生的**原始误差**（即量化值与原浮点值之差）。
    
2. **用 Hessian 逆“换算”误差**：
	这个误差不能直接平摊，需要除以一个系数。
	这个系数就是 Hessian 逆矩阵中对应这一列的对角线元素 [H−1]q
	可以理解为，它衡量了“这一列的误差，对最终输出影响的‘汇率’”。
    
3. **修正后续所有未量化的列**：
	用上一步算出的“归一化误差”，去更新从 q+1列到最后一列的所有权重。
	修正的方向和大小，由 Hessian 逆矩阵中对应的那一行（第 q 行）来决定。
	![[Pasted image 20261112180948.png]]


### 相比于OBS的工程优化
#### 利用列间的共享Hessian，实现按列并行量化
OBQ **原本需要为权重的每一行独立维护和更新 Hessian。**

GPTQ 的关键观察是：
	对于同一个线性层，Hessian H=XX⊤ 由输入激活 X 决定，**与权重的具体行无关**，
	因此所有行可以共享同一个 Hessian。
	这使得 GPTQ 可以按“列”为单位并行处理所有权重行，
	而**无需为每行单独更新 Hessian，大幅减少了计算量。**

#### 惰性批量更新
如果每量化一列就立刻更新所有右边的列，计算量太大（O (n²) 复杂度）。

**GPTQ，攒够一个block（eg 128列），再统一做一次批量更新**
- 块内逐列量化、逐列记录误差
- 块量化完了，一次性把累计的误差补偿应用到下一个块的列上
- 效果几乎一样快了好几倍


#### 用 Cholesky 分解替代显式的 Hessian 逆更新**  
OBQ 在每量化一个权重后，需要对 H^-1 进行行列移除操作来得到新的逆矩阵，这个过程在数值上不稳定，且累积误差容易导致 H−1H−1失去正定性。

GPTQ 改用 **Cholesky 分解**：
	预先对 HH 做分解（加入阻尼项保证正定），后续步骤通过三角矩阵的运算等价地实现误差补偿，
	避免了直接维护和更新 H−1，数值稳定性大幅提升，使得千亿参数级别的模型量化成为可能。


## AWQ：按激活找出要保护的通道
AWQ的核心思想，是认为：
	**一个特征维度的权重是否重要，取决于和它相乘的激活有多大**
	所以只要通过激活值的分布来识别出关键权重通道，并对这些通道进行等价缩放
	就可以在极低比特下降低量化误差

### 工作机制
#### 校准：获取每个通道的激活分布
**取一批真实数据x，跑模型获得每个权重对应的激活值，**
得到每个输入通道的平均绝对激活幅度

#### alpha网格搜索
缩放幅度 s 不能随意设定。
如果放得太大，其他不重要通道的权重分布可能被过度拉伸，反而增加误差。
AWQ 的做法是进行网格搜索：
在[0,1] 范围内按步长（通常默认 20 步）遍历一系列缩放比例系数 `ratio`，

用每个候选值生成缩放因子，然后**实际执行一次权重量化**，
并测量量化后输出与浮点基准输出之间的均方误差（MSE）。
选择使 MSE 最小的那个缩放因子作为该层的最优解。

- 具体公式为
	![[Pasted image 20261113152908.png]]
	其中 `act_mean` 是逐通道激活均值，`ratio` 是搜索变量。搜索的目标是让“保护重要通道”与“避免恶化其他通道”之间达到最优平衡。
	
#### 缩放后进行量化
选定一个缩放因子s
对于显著通道，先让权重除以s，对应通道的激活乘s
-> **缩小量化区间，从而减小INT4的量化误差**

**反量化时，再把原来的s乘回去**


### 权重缩放的目的和SmoothQuant对比
| 📊 方法       | 处理什么              | 缩放的方向          | 典型配置       |
| ----------- | ----------------- | -------------- | ---------- |
| SmoothQuant | 激活离群值让 INT8 激活难量化 | 压平激活，难度转给权重    | INT8 W8A8  |
| AWQ         | 显著通道的权重误差被大激活放大   | 放大显著权重，降低其相对误差 | INT4 W4A16 |


## Marlin：让解包不拖慢计算
编码后，正常的使用步骤，
是先把**整层 INT4 展开成 FP16 写回显存，再调用普通 GEMM**，
结果多了一次大规模读写，省下的带宽全吐了回去。

Marlin将**读权重、解包、反量化和矩阵乘法**，放进同一个Kernel流水线中
![[Pasted image 20261103174123.png]]

### 核心技术
#### 就地反量化，不落地显存
通做法：

```
从显存读 4-bit 权重 → 反量化成 FP16 → **写回显存** → 再读出来做矩阵乘法
         ↑ 来回搬，白忙活
```

Marlin 做法：

```
从显存读 4-bit 权重 → 直接在寄存器里解包成 FP16 → 立刻喂给 Tensor Core 做矩阵乘法
         ↑ 全程不落地，反量化和计算融合在一起
```

> 4-bit 权重只在显存里存一份，读进 GPU 寄存器后就地 "展开" 成 FP16，然后直接算，省掉了一次 "写回显存再读出来" 的往返。Jarvis Labs


#### 异步记载流水线，保证计算和访存重叠
GPU 算一块权重的时候，Marlin 已经让显存 "偷偷" 把下一块权重预取进来了：

```
时间轴：
  [算块0] [算块1] [算块2] [算块3]
          [取块1] [取块2] [取块3] [取块4]
```

计算和内存搬运**重叠进行**，不让 GPU 闲着等数据

#### 精细的任务调度
权重矩阵切成小 tile，每个 warp（GPU 线程束）负责一块，精心安排谁算哪块、什么时候同步，尽量让 Tensor Core 满负荷运转。
