
> W4A16，**让激活保留FP16/BF16， 只把权重压到4-bit**
> 问题在于，**4-bit的压缩表示，只有16个编码**，相比8-bit格距大了很多
> **关键在于让误差少伤输出**



## GPTQ：边量化边补偿

如果按照直觉，只按计算前的权重参数量化恢复，
目标即为最小化||W-W^||^2
（默认每个权重独立舍入，误差各自累积）

**但是经过线性层之后，有的误差会被输入放大，有的则会相互抵消**

**GPTQ的核心思路则是：**
	**在每次量化完一个权重后，把它造成的误差窟窿，**
	**用还没量化的权重给补回去**
	保证的是量化后的层输出，和量化前尽量一样，而不是看量化后的权重本身

### 工作机制
#### Hessian矩阵校准

用一小批真实数据X，计算Hessian矩阵：
![[Pasted image 20261103171705.png]]

每个元素H_ij，表示权重w_i变一点，对于输出的影响程度


#### 逐列量化 + 误差补偿
GPTQ 把权重矩阵 **按列（column）** 一列一列地处理，从左到右。
每处理一列，做三件事：

1. 量化当前列
	将当前列的FP16权重w_j, 
	就近舍入到 4-bit的网格上 得到q_j

2. 计算该列的权重误差
	error_j = w_j - q_j
	
3. 误差转接给还没量化的列
	**用 Hessian 的逆矩阵 \(H^{-1}\) 当 "分配表"，**
	**把当前列的量化误差，按合理比例分摊到右边还没碰过的所有列上：**
	![[Pasted image 20261103172041.png]]

#### 惰性批量更新
如果每量化一列就立刻更新所有右边的列，计算量太大（O (n²) 复杂度）。

**GPTQ，攒够一个block（eg 128列），再统一做一次批量更新**
- 块内逐列量化、逐列记录误差
- 块量化完了，一次性把累计的误差补偿应用到下一个块的列上
- 效果几乎一样快了好几倍



## AWQ：按激活找出要保护的通道
AWQ的核心思想，是认为：
	**一个特征维度的权重是否重要，取决于和它相乘的激活有多大**

### 工作机制
#### 校准：获取每个通道的激活分布
**取一批真实数据x，跑模型获得每个权重对应的激活值，**
**从而确定“显著通道”**

#### 缩放后进行量化
选定一个缩放因子s
对于显著通道，先让权重除以s，对应通道的激活乘s
-> **缩小量化区间，从而减小INT4的量化误差**

**反量化时，再把原来的s乘回去**


### 权重缩放的目的和SmoothQuant对比
|📊 方法|处理什么|缩放的方向|典型配置|
|---|---|---|---|
|SmoothQuant|激活离群值让 INT8 激活难量化|压平激活，难度转给权重|INT8 W8A8|
|AWQ|显著通道的权重误差被大激活放大|放大显著权重，降低其相对误差|INT4 W4A16|


## Marlin：让解包不拖慢计算
编码后，正常的使用步骤，
是先把**整层 INT4 展开成 FP16 写回显存，再调用普通 GEMM**，
结果多了一次大规模读写，省下的带宽全吐了回去。

Marlin将**读权重、解包、反量化和矩阵乘法**，放进同一个Kernel流水线中
![[Pasted image 20261103174123.png]]

### 核心技术
#### 就地反量化，不落地显存
通做法：

```
从显存读 4-bit 权重 → 反量化成 FP16 → **写回显存** → 再读出来做矩阵乘法
         ↑ 来回搬，白忙活
```

Marlin 做法：

```
从显存读 4-bit 权重 → 直接在寄存器里解包成 FP16 → 立刻喂给 Tensor Core 做矩阵乘法
         ↑ 全程不落地，反量化和计算融合在一起
```

> 4-bit 权重只在显存里存一份，读进 GPU 寄存器后就地 "展开" 成 FP16，然后直接算，省掉了一次 "写回显存再读出来" 的往返。Jarvis Labs


#### 异步记载流水线，保证计算和访存重叠
GPU 算一块权重的时候，Marlin 已经让显存 "偷偷" 把下一块权重预取进来了：

```
时间轴：
  [算块0] [算块1] [算块2] [算块3]
          [取块1] [取块2] [取块3] [取块4]
```

计算和内存搬运**重叠进行**，不让 GPU 闲着等数据

#### 精细的任务调度
权重矩阵切成小 tile，每个 warp（GPU 线程束）负责一块，精心安排谁算哪块、什么时候同步，尽量让 Tensor Core 满负荷运转。
