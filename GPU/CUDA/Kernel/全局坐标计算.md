> 众所周知，一个kernel程序的第一步是计算当前thread的索引idx
> 计算出的线程全局索引，联合设计的数据处理模式
> 才可以拿到对应线程的数据块


>CUDA的结构 不等于 GPU的内部结构
>CUDA的一个block，通常由一个SM负责
>一个SM中多个warp合作将thread对应到block中的thread执行任务


## CUDA的内置变量
| 变量                | 含义             | 维度范围                          |
| :---------------- | :------------- | :---------------------------- |
| `threadIdx.x/y/z` | 线程在**块内**的局部索引 | `0` ~ `blockDim-1`            |
| `blockIdx.x/y/z`  | 线程块在**网格内**的索引 | `0` ~ `gridDim-1`             |
| `blockDim.x/y/z`  | 每个块**每维**的线程数  | 由启动参数 `<<<..., threads>>>` 决定 |
| `gridDim.x/y/z`   | 网格**每维**的块数    | 由启动参数 `<<<grid, ...>>>` 决定    |

kernel的组织形式是以grid -> block -> thread构建的
并且grid和block的维度相同，且可以为多维


### 通用计算逻辑
不管维度是多少，全局索引的通用逻辑为：
	`块序号*块内线程数+局部线程索引`


### 边界保护
```cpp
if (global_id < N) {
    // 安全处理
}
```
必须加上这个判断，因为网格覆盖的**线程总数，往往是块大小的整数倍。**
有可能会超过总数据量N

###  二维坐标计算
在二维grid中，每个block也是二维的，
所以**需要在row方向和col方向上，分别施加通用的计算逻辑**

```cpp
int row = blockIdx.y * blockDim.y + threadIdx.y
int col = blockIdx.x * blockDim.x + threadIdx.x

if (row < height & col < width){
	int global_idx = row * width + col
}
```

> 为什么x对应col？**一般的内存访问优化**
> 一般的二维数组，是以行序存储，即同行的列元素顺序存放
> 所以如果col为x，
> 则有 `mat[row][0] mat[row][1] mat[row][2]...` 
> 达到相邻thread访问相邻元素的效果
> 
> 快速理解：
> 内存布局是行优先，x是变化最快的
> 因此让线程访问连续的x，实现合并内存访问


### 三维坐标计算
**原理类比于二维坐标计算**

```cpp
int x = blockIdx.x * blockDim.x + threadIdx.x;
int y = blockIdx.y * blockDim.y + threadIdx.y;
int z = blovkIdx.z * blockDim.z + threadIdx,z;

if (x < dimX && y < dimY && z<dimZ){
	int global_idx = z * dimY * dimX + y * dimX + x;
}
```

## 相关配置
CUDA规定单个block内的线程数不能超过1024

```cpp
// 一维配置
int blocksPerGrid = (N + threadsPerBlock - 1) / threadsPerBlock //保证向上取整
kernel<<<blockPerGrid, threadPerBlock>>>(d_data, N);


//二维配置
dim3 blockSize(16, 16); //16*16 =256 < 1024
dim3 gridSize( (width+15)/16, (height+15)/16 );
kernel<<<gridSize, blockSize>>>(d_image, width, height);


//三维配置
dim3 blockSize(8, 8, 4); //8*8*4 = 256 < 1024
dim3 gridSize((dimX+7)/8, (dimY+7)/8, (dimZ+3)/4);
kernel<<<gridSize, blockSize>>>(d_volume, dimX, dimY, dimZ);
```

- threadPerBlock：块内线程数
	**通常 设置为32的整数倍**，因为单个Warp是32个线程
	保证不浪费Warp资源

- blockPerGrid：
	加上块内线程数-1， 保证向上取整
	才能覆盖全部数据

### 关于dim3
- 没有赋值的维度默认为 1。
	例如 dim3 block(32, 32) → block.z = 1。
- 内核中访问 threadIdx.z 是安全的，
	但如果启动时没给 z 值（或给了1），它始终为 0。
- 用整数直接传给 <<<>>> 时，相当于只设置了 .x 分量。
	例如 kernel<<<10, 256>>> 等价于 gridDim.x=10, blockDim.x=256，其他维为1。
