## V0: 朴素的计算
**按照最朴素的矩阵乘法运算规则，**
**每个线程负责C矩阵的一个位置运算结果`C[i][j]`**

那么 `C[i][j] = A[i] * B[j] = for(k) {sum += A[i][k] * B[k][j]}`

![[Pasted image 20261107152057.png]]

### 性能瓶颈
`C[i][j] = A[i] * B[j]` 由于每个元素负责一个C位置，
所以对于，同一行的C元素，**对应的线程都会重复读取A的同一行**
重复访问global memory，导致memory bound


## V1： Tile版本
由上文的性能瓶颈可知，
可以将需要重复读取的A、B数据搬运到shared memory
读取这一部分共享数据的thread组成一个cuda block，进行运算

### 实现机制
Kernel的启动参数，大致为
```cpp
dim3 block(BN, BM);                          // 比如 (8, 8)
dim3 grid((N + BN - 1)/BN, (M + BM - 1)/BM); // 向上取整
```
保证一个block对应一个C tile， block数量覆盖所有的C tile

1. 把输出矩阵分成若干[BM，BN]的块
2. 计算过程中，A和B沿着K轴分成BK大小的块
3. 每次迭代把`A[BM][BK]和B[BK][BN]`加载到共享内存中
4. 线程块内所有线程从共享内存中读数据，完成局部乘加
5. 循环到下一个K分块，直到遍历完整个K

**每个A、B中的元素被加载到共享内存后，**
**可以由线程块内BM×BNB个线程共用，**
全局访存量下降为原来的`(1/(BM * BN))`量级（粗略估计），缓解带宽瓶颈。



![[Pasted image 20261107153339.png]]

### 性能瓶颈
虽然改善了访存效率，但是计算方式仍然是一个线程对应C的一个位置

在一次Tile迭代中，只做了2次`global load`，
进行了32次`shared memory load`，还有32次FMA，然后就开始sync。 
**线程的大部分时间都在等待同步、等待load完成，计算密度太低。**


## V1 1D Thread

1D Tiling的核心思想
是让一个线程负责多个元素，而不是一个。 
我们可以让一个线程

线程(ty=0,tx=0)可以负责row[0, 15]， 线程(ty=1,tx=0)负责row[16, 31]…

所有的(ty, tx)线程的列 `col = blockCol + tx`。

这就是我们这个方法的核心，通过增加计算密度，还overlap访存效率的低下。
