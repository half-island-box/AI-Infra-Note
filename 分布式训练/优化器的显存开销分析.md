反向传播**依靠优化器来决定权重参数的变化方向**
但是优化器在Infra领域，还会偷偷占掉训练显存的一大半


## 优化器概述
### 在训练中的位置
放在一个训练的循环中，它的位置非常固定，
位于“算完梯度”和“下一轮前向传播”之间：

![[Pasted image 20261013102614.png]]

```python
for batch in dataloader:
    loss = model(batch)          # 前向：算预测、算损失
    loss.backward()              # 反向：算出每个参数的梯度
    optimizer.step()             # 优化器：结合梯度 + 内部状态更新参数
    optimizer.zero_grad()        # 清零梯度，准备下一轮

```

- optimizer.step()背后实际做了三件事：
	读取每个参数的梯度
	结合优化器自己维护的内部状态（动量、二阶矩等）算出更新量
	更新量应用到参数上

### 优化器的演进：从SGD到AdamW
优化器的演进，本质上是一个“给参数增加更多辅助信息”的历史
辅助信息越多，收敛更快更稳定，**代价就是每个参数需要多保存一份状态**

| ⚙️ 优化器   | 更新用到的信息                | 每参数额外状态     | 典型场景               |
| -------- | ---------------------- | ----------- | ------------------ |
| SGD      | 当前梯度                   | 0 份         | 简单凸问题、教学           |
| Momentum | 梯度 + 一阶动量              | 1 份（mm)     | CV 里的 SGD+Momentum |
| Adam     | 梯度 + 一阶 + 二阶动量         | 2 份（m,vm,v) | 通用默认               |
| AdamW    | 同 Adam，解耦 weight decay | 2 份（m,vm,v) | 大模型训练标准            |

#### SGD
更新规则 θt+1​=θt​−η⋅g，即 `新权重=老权重-学习率*梯度`

这是最朴素的做法，可以类比为蒙着眼下山，只看脚下最陡峭的方向迈一步
简单，但是容易在狭长的山谷里左右横跳


#### Momentum SGD：动量辅助的SGD
给参数更新增加了“惯性”：维护一阶动量   mt=βmt−1+gt​
即 `新动量=动量系数*老动量+梯度`

更新规则：θt+1​=θt​−η⋅mt

类比为将滚下山的球换成带有惯性的铅球
滚下山不会被小坑绊住，震荡也被平滑掉，但是代价就是多存了一份一阶动量


#### Adam：自适应学习率
由于不同参数的梯度差异巨大：
梯度一直很大：固定学习率容易震荡
梯度一致很小：固定学习率不更新

**所以Adam的想法即用二阶动量，来给每个参数单独维护一个自适应的学习率**

核心更新规则：
![[Pasted image 20261013104757.png]]​​
其中 m^t,v^tm^t​,v^t​ 是对 mt,vtmt​,vt​ 做偏差修正后的结果
（初期 m0=v0=0m0​=v0​=0 会让估计偏小，需要除以 1−βt1−βt 修正）

分母上的 v^t就是”自适应”的来源：
历史梯度大的参数分母大、步子收着点，
一直很小的参数分母小、步子放大点。

代价就是每个参数需要多存 一阶动量 和 二阶动量 两份状态

#### AdamW：改进权重衰退
根据L2正则化，有权重衰退公式：gt​=∇f(θt−1​)+λ⋅θt−1
该公式将梯度和权重混合
​
朴素Adam的参数优化公式，由于学习率在每个步长会自适应
导致某个权重的每一步权重衰退的力度不再统一

所以AdamW将权重衰退从梯度里拿出来，变成一份独立的参数缩放：
θt+1​←θt+1​−ηλθt​
从而与梯度更新彻底解偶

> L1和L2正则化，**都是用于解决模型权重过大容易导致过拟合的问题：**
> 模型权重过大 -> 输入的小噪声变化也会被放大 -> 对输入极其敏感
> 即使模型达到训练集要求，也会在测试集表现不佳
> 所以需要权重衰退来适当减小权重，从而提高模型泛化性


## 优化器的显存开销
下面的分析都**以混合精度训练**为前提：
前向和反向用 BF16/FP16 提速，优化器内部一律用FP32保证精度

>优化器为什么不也用 BF16 省一半显存？
>答案藏在”更新量太小”这件事上：
>
每一步的参数更新量约等于 学习率 × 梯度，量级常在 10^-4甚至更小。BF16 只有 7 位尾数（fraction），相对精度很粗，表示不了这么小的变化——加到较大的参数上等于没加（大数吃小数）
训练要跑成千上万步，每步的舍入误差会不断累积，用**低精度存参数最终会导致训练发散**。

### 每参数要为优化器付出多少显存
先按”每个参数额外存几份 FP32”来数账（FP32 每个数 4 字节）：

| ⚙️ 优化器       | 额外状态      | 每参数优化器显存                          | 7B 模型优化器开销 |
| ------------ | --------- | --------------------------------- | ---------- |
| SGD          | 无         | 4 B（仅 FP32 参数副本）                  | ~28 GB     |
| Momentum SGD | 一阶动量      | 8 B（FP32 副本 + FP32 动量）            | ~56 GB     |
| Adam / AdamW | 一阶 + 二阶动量 | 12 B（FP32 副本 + FP32 mm + FP32 vv） | ~84 GB     |
### 一次训练的完整显存占用
以 AdamW + BF16 训练 7B 模型为例，完整的显存账本是这样的：

```
BF16 参数=2×7×10^9=14 GB
BF16 梯度​=2×7×10^9=14 GB​
优化器状态=12×7×10^9=84 GB​
（FP32 主权重 28 + 一阶动量 28 + 二阶动量 28）合计≈112 GB
```

​
也就是说，光是”模型 + 梯度 + 优化器”这三样静态开销就要 112 GB，其中**优化器状态一家独占约 75%**（还没算激活值）。

这直接解释了ZeRO的设计动机：
ZeRO-1 第一刀就砍向优化器状态，因为它是显存占比最大的一块，切它的性价比最高。

## 大Batch优化器：LARS 和 LAMB

分布式本身会给优化器出难题：
数据并行有个直接副作用
——有效 Batch Size 被线性放大。用 N 张卡做数据并行，全局 Batch 就是单卡的 N 倍。

### 大Batch 为什么容易训练不稳定
1. Batch越大，梯度是越多样本的平均，方差更小
	理论上可以配更大的学习率来加速收敛

2. 实践中放大学习率，训练往往一开始就震荡甚至发散

3. 更麻烦的是，模型里不同层的参数尺度差异极大（比如 Embedding 层和 LayerNorm 层根本不是一个量级），用一个全局统一的学习率去伺候所有层，怎么调都顾此失彼。

所以从根因出发，需要**用逐层的、自适应的学习率，而不是一刀切**的

>在动用 LARS/LAMB 之前，工程上先试两招更简单的：
>一是**线性缩放规则**（Batch 放大 k 倍，学习率也放大 k 倍）；
>二是**学习率 warmup**（前几百到几千步让学习率从很小线性爬到目标值，避开训练初期的剧烈震荡）。
>只有两者都失效时，才轮到逐层自适应的LARS/LAMB


> 注意：Adam和LAR的“自适应”维度不同：
> Adam 是让每个参数有自己的学习率，不和其他参数共享
> LAR是让每个Layer有自己的更新缩放比，同个Layer中的参数更新缩放比相同，不意味着学习率相同


### LARS：给每一层单独定步长（缩放）
LARS（Layer-wise Adaptive Rate Scaling）的思路是给每层算一个专属的缩放因子，大致正比于”参数范数 / 梯度范数”：


![[Pasted image 20261013204243.png]]

直觉是：
参数本身很大、但梯度很小的层，说明它更新得太保守，可以放开步子迈大点；
反过来梯度相对参数很大的层，就得收着点防止跑飞。LARS 最早是为 ResNet 的大 Batch 训练设计的。

### LARB：把LARS的思想搬进Adam
LAMB（Layer-wise Adaptive Moments）可以理解为 **Adam + 逐层信赖域缩放**：

- 每层的更新量先由 Adam 正常算出（已经带了自适应学习率）；
- 再乘上一个逐层的信赖域缩放因子 ϕ(∥θl∥)/∥rl∥ϕ(∥θl​∥)/∥rl​∥，把这层的更新幅度约束在合理范围内。

它最著名的战绩是把 BERT 预训练的 Batch Size 拉到 65536 还能稳定收敛，训练时间从 3 天压到 76 分钟。

把两者放一起对比，区别就清楚了：

|🔧 优化器|基础|缩放粒度|主要战场|
|---|---|---|---|
|LARS|SGD + Momentum|逐层（参数范数/梯度范数）|ResNet 等 CV 大 Batch|
|LAMB|Adam|逐层（信赖域 × Adam 更新）|BERT/Transformer 大 Batch|
